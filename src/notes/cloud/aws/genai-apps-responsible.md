# FM 應用、負責任 AI 與 AI 安全治理

> 對應 AIF-C01 的 Domain 3（Foundation Model 的應用，28%）、Domain 4（負責任的 AI，14%）、Domain 5（AI 的安全、合規與治理，14%）。Domain 3 是配分最高的範疇。

## 推論參數

這些參數在推論時調整，**不需要重新訓練模型**。

| 參數 | 作用 | 調低 | 調高 |
| --- | --- | --- | --- |
| Temperature | 控制輸出的隨機程度 | 穩定、保守、適合事實性回答 | 多樣、有創意、較容易出錯 |
| Top P | 只從累積機率達到 P 的候選字中挑選 | 輸出較集中 | 輸出較多樣 |
| Top K | 只從機率最高的 K 個候選字中挑選 | 輸出較集中 | 輸出較多樣 |
| 最大輸出長度 | 輸出 token 的上限 | 回答較短、成本較低 | 回答可較長 |
| Stop sequence | 遇到指定字串就停止輸出 | | |

## RAG

RAG（Retrieval Augmented Generation）是在回答前先從外部知識庫檢索相關內容，連同問題一起交給模型，讓回答有依據。

1. **事前準備**：把文件切塊、轉成 embedding、存進向量資料庫。
2. **使用者提問**：把問題也轉成 embedding。
3. **檢索**：在向量資料庫找出語意最接近的段落。
4. **增強**：把檢索到的段落與問題組成 prompt。
5. **生成**：模型根據這些段落回答，並可附上來源。

| RAG 的好處 | 說明 |
| --- | --- |
| 使用最新與私有的資料 | 不必重新訓練模型 |
| 減少幻覺 | 回答以檢索到的內容為依據 |
| 可附來源 | 使用者能查證 |
| 成本低於微調 | 更新知識只要更新文件 |

Bedrock Knowledge Bases 是受管的 RAG 方案，上述步驟都由它處理。

| 可存放向量的 AWS 服務 | 特點 |
| --- | --- |
| OpenSearch Service | 最常見的選擇，含無伺服器版本 |
| Aurora PostgreSQL、RDS for PostgreSQL | 以 pgvector 擴充套件存向量，適合已使用關聯式資料庫的情境 |
| Neptune | 圖形資料庫，可結合知識圖譜做檢索 |
| DocumentDB、MemoryDB | 文件資料庫與記憶體內資料庫的向量搜尋 |
| S3 Vectors | 以物件儲存的成本存放大量向量 |

## 客製化方式的比較

由上到下，**成本、所需資料與技術門檻遞增**。題目問最省錢或最快時，從最上面開始選。

| 方式 | 做法 | 是否改變模型 | 成本 | 何時選 |
| --- | --- | --- | --- | --- |
| Prompt engineering | 調整指令與範例 | 否 | 最低 | 第一步都先試這個 |
| In-context learning | 在 prompt 裡放範例（few-shot） | 否 | 低，但 prompt 變長 | 要模型照特定格式或風格 |
| RAG | 檢索外部資料放進 prompt | 否 | 中 | 需要最新或私有的知識 |
| 微調 | 用有標籤的資料繼續訓練 | 是 | 高 | 需要特定語氣、格式或專門任務 |
| 持續預訓練 | 用無標籤的領域資料繼續訓練 | 是 | 高 | 讓模型熟悉某個領域的用語 |
| 蒸餾 | 用大模型的輸出訓練小模型 | 產生新的小模型 | 訓練一次，之後推論便宜 | 要降低推論成本與延遲 |
| 從頭預訓練 | 自己訓練 FM | 是 | 最高 | 幾乎不會是答案 |

**RAG 提供的是知識，微調改變的是行為；資料經常更新時選 RAG。**

## Prompt 設計

| 組成 | 說明 |
| --- | --- |
| 指令（Instruction） | 要模型做什麼 |
| 脈絡（Context） | 背景資訊、角色設定、參考資料 |
| 輸入資料 | 要處理的內容 |
| 輸出格式 | 希望的格式、長度、語氣 |
| Negative prompt | 明確說明不要出現什麼，常用於影像生成 |

| 技巧 | 做法 | 何時用 |
| --- | --- | --- |
| Zero-shot | 只給指令，不給範例 | 簡單、常見的任務 |
| Single-shot（One-shot） | 給一個範例 | 需要示範格式 |
| Few-shot | 給數個範例 | 需要模型照特定模式輸出 |
| Chain-of-thought | 要求模型一步一步推理 | 需要推理、計算的複雜問題 |
| Prompt template | 留有變數位置、可重複使用的 prompt | 把 prompt 標準化並套用到不同輸入 |

最佳實務：指令具體而簡潔、提供脈絡、指定輸出格式、反覆試驗比較、搭配 Guardrails。Bedrock Prompt Management 用來保存 prompt、管理版本並在應用間共用。

### Prompt 的風險

| 風險 | 說明 |
| --- | --- |
| Prompt injection | 在輸入中夾帶指令，讓模型違背原本的指示 |
| Jailbreaking | 用話術繞過模型的安全限制，讓它產出本來會拒絕的內容 |
| Hijacking | 把模型的行為導向攻擊者的目的 |
| Exposure（Prompt leaking） | 誘使模型洩漏系統 prompt 或其他敏感資訊 |
| Poisoning | 在訓練資料或知識庫中植入惡意內容，影響模型輸出 |

## 訓練與微調名詞

| 名詞 | 說明 |
| --- | --- |
| 預訓練 | 用大量無標籤資料訓練出通用的 FM |
| 微調 | 用有標籤的資料讓模型適應特定任務 |
| 持續預訓練 | 用無標籤的領域資料讓模型吸收領域知識 |
| 蒸餾 | 把大模型（老師）的能力轉移到小模型（學生） |
| Instruction tuning | 用「指令加上期望回答」的成對資料微調，讓模型更會照指令做事 |
| Transfer learning | 把在一個任務學到的知識用到另一個相關任務；微調就是一種 |
| RLHF | 用人類對輸出的評分作為回饋訊號來改進模型 |

微調資料的重點：經過整理與篩選、有足夠數量、標註正確、能代表實際使用情境、符合治理與授權規範。

## 評估 FM

| 評估方式 | 說明 | 何時用 |
| --- | --- | --- |
| 自動指標 | 用演算法比對輸出與參考答案 | 快速、大量、可重複 |
| 基準資料集 | 用公開的標準題庫比較不同模型 | 客觀比較模型 |
| LLM-as-a-judge | 用另一個模型為輸出評分 | 比人工便宜，又能評語意品質 |
| 人工評估 | 由人判斷品質、語氣、是否符合品牌 | 主觀品質、最終把關 |

| 指標 | 衡量什麼 | 典型任務 |
| --- | --- | --- |
| ROUGE | 輸出與參考答案的詞組重疊，偏重 recall | 摘要 |
| BLEU | 輸出與參考譯文的詞組重疊，偏重 precision | 翻譯 |
| BERTScore | 用 embedding 比較語意相似度，不要求用字相同 | 摘要、改寫等重語意的任務 |
| Perplexity | 模型對文字的預測把握程度，越低越好 | 語言模型本身的品質 |

對應用程式的評估要看整個系統：RAG 看檢索是否相關、回答是否忠於來源；agent 看任務是否完成、工具是否用對。Bedrock Model Evaluation 支援上述方式，也能評估 RAG。

## 負責任的 AI

| 面向 | 意義 |
| --- | --- |
| 公平性 | 對不同族群的結果沒有不當的差異 |
| 可解釋性 | 能說明模型為何做出某個輸出 |
| 隱私與安全 | 妥善取得、使用並保護資料與模型 |
| 安全性（Safety） | 防止有害的輸出與濫用 |
| 可控性 | 有機制監控並引導 AI 的行為 |
| 真實性與穩健性 | 即使遇到非預期或惡意的輸入，仍能產生正確的輸出 |
| 治理 | 在整個 AI 供應鏈落實最佳實務與問責 |
| 透明度 | 讓利害關係人了解系統的能力、限制與使用方式 |

### 偏差與變異

| 狀況 | 現象 | 原因 | 改善 |
| --- | --- | --- | --- |
| Underfitting | 訓練資料與新資料都表現差 | 模型太簡單，偏差高 | 用較複雜的模型、增加特徵、訓練更久 |
| Overfitting | 訓練資料表現好，新資料表現差 | 模型記住了訓練資料，變異高 | 增加資料、正則化、提早停止、簡化模型 |

| 資料偏差的來源 | 說明 |
| --- | --- |
| 抽樣偏差 | 訓練資料不能代表實際的使用族群 |
| 類別不平衡 | 某些族群或類別的資料太少 |
| 標註偏差 | 標註者的主觀判斷不一致或帶有成見 |
| 歷史偏差 | 資料忠實反映了過去既有的不公平 |

### GenAI 的法律與商業風險

智慧財產侵權、有偏差的輸出造成歧視、幻覺導致錯誤資訊、失去客戶信任、終端使用者依賴錯誤或有害的內容。選擇模型時也要考量環境面：模型越大，訓練與推論耗用的能源越多，夠用的小模型較符合永續原則。

### 透明度與可解釋性

| 名詞 | 意義 |
| --- | --- |
| 透明度 | 公開模型的來源、訓練資料、限制與使用方式 |
| Interpretability | 能直接理解模型內部如何運作，例如線性迴歸、決策樹 |
| Explainability | 即使模型是黑箱，也能事後說明它為何產生某個輸出 |

模型越複雜，效能通常越好，但越難解釋；法規要求能解釋決策時，可能要犧牲一些效能改用較簡單的模型。以人為本的設計原則：讓使用者知道自己正在與 AI 互動、說明決策的依據、提供回饋與申訴的管道、保留人工介入的機會。

## AI 的安全、合規與治理

### 共同責任

AWS 負責雲端**本身**的安全（設施、硬體、受管服務的基礎設施）；客戶負責雲端**裡面**的安全：資料、存取權限、prompt 內容、應用程式、如何使用模型的輸出。

### 保護 AI 系統的服務

| 服務或功能 | 在 AI 情境的用途 |
| --- | --- |
| IAM 角色與政策 | 以最小權限控制誰能呼叫模型、存取訓練資料 |
| KMS | 加密訓練資料、模型與知識庫 |
| Macie | 找出 S3 訓練資料中的 PII |
| PrivateLink | 讓對 Bedrock、SageMaker 的呼叫不經過公開網際網路 |
| Secrets Manager | 保存 agent 與應用使用的 API 金鑰與憑證 |
| Bedrock Guardrails | 過濾輸入與輸出、遮蔽敏感資訊 |
| AgentCore Identity／Policy | 管理 agent 的身分並限制它可執行的動作 |
| CloudTrail、CloudWatch | 稽核誰呼叫了哪些 API；監控並可開啟 Bedrock 的模型呼叫紀錄 |

### AI 特有的威脅與對策

| 考量 | 說明 | 對策 |
| --- | --- | --- |
| Prompt injection | 惡意輸入改變模型行為 | Guardrails、輸入驗證、限制 agent 權限 |
| 資料外洩 | 模型輸出洩漏訓練資料或其他使用者的資訊 | 敏感資訊過濾、存取控制、不把機密放進訓練資料 |
| 訓練資料汙染 | 惡意資料影響模型 | 管控資料來源、驗證資料品質 |
| 有害與毒性內容 | 輸出仇恨、暴力等內容 | Guardrails 的內容過濾 |
| 不當的輸出處理 | 未檢查就把模型輸出交給下游系統執行 | 輸出過濾與驗證 |
| 稽核需求 | 需要追查 AI 互動的紀錄 | 模型呼叫紀錄、CloudTrail |

**偵測幻覺的做法**：RAG grounding、來源引用、輸出驗證（規則或另一個模型）、信心分數低於門檻改人工或拒答、Guardrails 的 contextual grounding 檢查。

### Generative AI Security Scoping Matrix

依客戶對模型與資料的掌控程度，把 GenAI 的使用方式分成五個範圍；**越往下，客戶要負的安全責任越多**。

| 範圍 | 類型 | 例子 |
| --- | --- | --- |
| Scope 1 | 消費級應用 | 直接使用公開的 GenAI 聊天服務 |
| Scope 2 | 企業級應用 | 使用內建 GenAI 功能的第三方企業軟體 |
| Scope 3 | 預訓練模型 | 透過 Bedrock 的 API 用現成 FM 建構自己的應用 |
| Scope 4 | 微調模型 | 用自己的資料微調 FM |
| Scope 5 | 自行訓練模型 | 從頭用自己的資料訓練模型 |
