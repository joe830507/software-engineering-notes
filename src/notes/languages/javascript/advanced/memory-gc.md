# 記憶體與垃圾回收

## 垃圾回收機制

現代引擎用的是**標記清除**（mark-and-sweep）：從根（全域物件、目前的呼叫堆疊）出發，標記所有能到達的物件，沒被標記到的就是垃圾，可以回收。所以循環參考不是問題，只要整組物件從根到達不了，就會一起被回收。

V8 的做法：

- **分代回收**：大多數物件很快就沒用了，所以堆積分成新生代和老生代。新生代空間小，用 Scavenge 演算法（複製存活物件到另一半空間）頻繁快速地回收；存活過兩次的物件晉升到老生代，用標記清除加標記整理處理。
- **減少停頓**：增量標記、並行標記、並行清除，把工作拆小或交給背景執行緒，降低主執行緒停頓。
- 舊的**參考計數**演算法無法處理循環參考，早期 IE 的 DOM 和 JavaScript 物件循環參考會洩漏，這是很多舊面試題的來源，現在已經不適用。

## 常見的記憶體洩漏

本質都是「不再需要的物件，仍然被長期存在的東西引用著」。常見的有五種：

1. **意外的全域變數**：非嚴格模式下對未宣告的變數賦值。
2. **忘記清除的計時器**：`setInterval` 的回呼引用了元件或大資料。
3. **忘記移除的事件監聽**：尤其是在 `window`、`document` 上註冊的監聽，元件卸載後還在。
4. **脫離 DOM 的節點**：節點已從頁面移除，但 JavaScript 變數仍然引用著，整棵子樹都無法回收。
5. **無上限的快取**：用 `Map` 或物件當快取但從不清除。

修法：

- 在元件的卸載階段（React 的 effect cleanup、Vue 的 `onUnmounted`）清除計時器和監聽。
- 用 `AbortController` 一次移除多個監聽。
- 快取設上限（LRU）或改用 `WeakMap`。

## 二進位資料

`ArrayBuffer` 是一段固定長度的原始二進位記憶體，本身不能直接讀寫；TypedArray（`Uint8Array`、`Float64Array` 等）是用固定的數字型別「看」這段記憶體的視圖；`DataView` 可以用任意型別、任意位元組順序讀寫，適合解析二進位協定。

用途：檔案處理、WebSocket 二進位訊息、WebGL、WebAssembly、加密。

```js
const bytes = new TextEncoder().encode("Hi");
bytes;                           // Uint8Array(2) [ 72, 105 ]
bytes.toBase64();                // SGk=（ES2026）
bytes.toHex();                   // 4869（ES2026）
Uint8Array.fromBase64("SGk=");   // Uint8Array(2) [ 72, 105 ]
```

Base64 / Hex 轉換是 ES2026 的新方法，支援度以 MDN 相容性表為準。
