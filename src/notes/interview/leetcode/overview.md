# 刷題方法與面試流程

> 範例是 Java（17 相容語法）。34 題主要解法已在 JDK 21 編譯，並通過本機的範例、邊界與隨機差異測試；這是本機驗證，不代表已向 LeetCode 提交或涵蓋所有隱藏測資。

## 題單怎麼選

市面上的刷題清單很多，真正被大量公司驗證過、值得投入時間的主要是兩個：

- **NeetCode 150**：依資料結構與演算法分成 18 個分類、共 150 題，是目前最被廣泛使用的刷題路線圖。
- **Tech Interview Handbook（Best Practice Questions）**：5 週的漸進式題單，約 60 題，偏向「最短時間內覆蓋最高頻考點」。

兩份題單比對後會發現，Tech Interview Handbook 的題目幾乎完全被 NeetCode 150 包含，所以不需要分別刷兩份清單。時間非常緊迫時，可以先刷有 Handbook 標記的題目，再回頭補完整份 NeetCode 150。

這份筆記以**模式**為主幹，收錄約 50 題的 Java 解法，每題都有思路、程式碼、複雜度和注意事項。官方的 [Top Interview 150](https://leetcode.com/studyplan/top-interview-150/) 與 [LeetCode 75](https://leetcode.com/studyplan/leetcode-75/) 也可以用來擴充覆蓋範圍。

## 有幾點要先說清楚

這是對一些常見說法的修正：

| 常見說法 | 比較準確的說法 |
| --- | --- |
| 約 70% 面試題是 Medium | 沒有樣本、公司、地區、職級或年份，不能當作可靠統計。可以改成「以 Medium 作為主要練習範圍，並用 Easy 建立基本功」。 |
| HashMap 搜尋 O(1) | 應標示**平均 / 期望** O(1)，不是任意輸入下的嚴格最壞保證；雜湊字串本身也有字串長度成本。 |
| 二元樹與圖都是樹狀遍歷 | 圖可能有環、多條路徑與不連通分量，需要 visited 或其他狀態；一般圖遍歷成本是 O(V+E)。 |
| 二分搜尋與排序都是 O(log n) | 二分搜尋在可排除半邊時才是 O(log n)；排序合併是 O(n log n)。二分也可用在具單調性的「答案空間」，不限已排序陣列。 |
| 遞迴解法空間很小 | 呼叫堆疊必須計入。二元樹 DFS 是 O(h)，偏斜樹可達 O(n)。 |
| 滑動窗口可套所有連續區間 | 需要可維護、可安全縮放的條件。含負數的子陣列和問題常需前綴和加雜湊。 |
| DP 是面試高分水嶺 | 這是主觀描述。面試也看需求釐清、正確性論證、複雜度、測試與溝通，不能只押 DP。 |

## 刷題的正確方法：三輪法

**錯誤做法：閱讀理解式刷題**。看題 → 想 5 分鐘 → 想不出來 → 看答案 → 「喔原來如此」→ 下一題。「看答案然後理解」訓練的是閱讀理解能力，而面試考的是在完全沒有答案、時間有限、有人盯著你看的壓力下，從零想出解法的能力，兩者重疊的程度比大多數人以為的低得多。

### 第一輪：理解模式

1. 想 15 分鐘。想不出來就看解答，但**只看思路，不看程式碼**。
2. 理解思路後，自己把程式碼寫出來。寫不出來就再看一次思路，看完再寫，直到能獨立寫完整段程式碼。
3. 寫完後記下兩件事：這題屬於什麼模式？關鍵洞察是哪一句話？這份筆記就是第三輪前唯一需要複習的材料。

### 第二輪：鞏固（隔 3～7 天）

只看題目，不看筆記，直接寫。「隔幾天再做」很關鍵，記憶在快要遺忘的臨界點被重新喚起，鞏固效果遠高於當天重複練習（間隔效應）。寫不出來就標記為「弱項」，不要當下又看答案。

### 第三輪：面試前一週

只做弱項清單，加上每個模式挑 2 題代表題快速過一遍手感。目標是 **20 分鐘內**從讀題到寫完可執行的程式碼，模擬真實面試的節奏。

## 面試時的標準流程

面試官評分時，「有沒有走完這個流程」往往比「有沒有寫出最佳解」影響更大。面試官沒辦法讀你的心，你不講出來，他就只能看著你打字。

| 步驟 | 建議時間 | 該做的事 |
| --- | --- | --- |
| 1. 澄清題目 | 2 分鐘 | 「輸入可以是空的嗎？」「有負數嗎？」「陣列多大？」「有重複元素嗎？」「要回傳索引還是值？」很多題目的正確解法會因為這些條件而完全不同。 |
| 2. 舉例驗證理解 | 1 分鐘 | 手動跑一個小例子，確認你理解題意，也讓面試官看到你的思考過程是具體的。 |
| 3. 先講暴力解 | 2 分鐘 | 「最直觀的做法是雙迴圈，O(n²)。」這一步不能跳過，面試官要看到你有一個 baseline。 |
| 4. 找瓶頸，提出優化 | 3 分鐘 | 「重複的部分是 XXX，可以用雜湊表記下來，變成 O(n)。」寫程式前先跟面試官確認方向。 |
| 5. 寫程式碼 | 10 分鐘 | 邊寫邊講，變數命名要有意義（不要用 `a`、`b`、`tmp1`）。 |
| 6. 自己跑測資 | 3 分鐘 | 一定要主動做，用一個小例子逐行走一次，同時也是替自己 debug 的機會。 |
| 7. 討論複雜度與邊界 | 2 分鐘 | 時間、空間、空輸入、單元素、溢位。主動提出比被動回答分數更高。 |

**最關鍵的一句話**：面試不是考你會不會這題，是考你不會的時候怎麼思考。所以「講出你的思考過程」比「直接寫出最佳解」更重要。

## 每題怎麼讀

每題依序列出：題意、範例、解題思路、完整主要解法、複雜度、注意事項。

- 提交時只貼該題的 `class Solution`，並在檔案頂端加 `import java.util.*;`。`LRUCache`、`MinStack` 等設計題是獨立的類別。
- 不要把全部 `class Solution` 貼到同一個 Java 檔案，它們是不同題目的獨立答案。
- LeetCode 已提供 `ListNode` 與 `TreeNode`，本機執行時要自己補上定義（在鏈結串列與二元樹那兩頁有）。
- 會修改輸入的解法：#206、#21 修改串列連結；#226 修改樹；#200 修改網格。#15、#56 則複製後排序。

本機使用例：

```java
public class Main {
    public static void main(String[] args) {
        int[] answer = new Solution().twoSum(new int[]{3, 2, 4}, 6);
        System.out.println(Arrays.toString(answer)); // [1, 2]
    }
}
```

執行：`javac Main.java`，再執行 `java Main`。

這是依先備知識安排的學習順序，不代表出題頻率排名。

2. **建立常用模式**：#49、#128、#11、#15、#3、#102、#98、#200、#56、#53、#198。
3. **練狀態與設計**：#155、#739、#236、#46、#78、#22、#33、#146。
4. **處理較難轉移與邊界**：#322、#300、#1143、#42、#76。

### 怎樣算「會做」

每題做到下列五點，再視為「會做」：

- 能先說明暴力解為何昂貴，以及目前解法省掉哪些重複工作。
- 能精確定義狀態或不變量，例如「left 永不往左退」、「stack 只存尚未結算的日期」。
- 不看答案完成實作，並能說明重要條件中的 `<` 與 `<=` 為何如此選擇。
- 主動檢查空 / 最小輸入、重複值、全負數、偏斜樹、無解等適用案例。
- 分清平均與最壞複雜度、工作空間與輸出空間，能指出是否修改輸入。

不要只背程式：例如 #3 與 #76 都是窗口，但前者維持「沒有重複」，後者維持「覆蓋需求次數」，更新條件不能直接互換。

## 時間不同的讀法

- **4 週以上**：先讀「解題模式速查」建立模式地圖，再依分類逐題做三輪法。
- **2～3 週**：快速瀏覽模式速查表，直接進入各分類，優先做「建議練習順序」裡的題目，每題做完整的第一輪。
- **不到 1 週**：直接照「建議練習順序」的第 1、2 組做，每題只求「思路 + 關鍵洞察」看懂。
